# LLM 总结 Prompt 模板

> Step 2 用。这是给主 LLM(你自己)的合成指南,**不是**调外部 LLM API 的 prompt。读完这份 + `report-template.md`,直接生成 XML 即可。

## 输入

你拿到的是:
1. L1-L4 抓取的原始数据(JSON / Markdown,来自 fetchers)
2. 用户原始输入(老师名 + 学校 + 可选方向)

## 输出

> **🚨 Output Discipline (v0.11.0+, 2026-06-11)**: LLM 在跑这个 prompt 之前/之中, **禁止在 chat 输出 4 行元信息 preamble** (「本报告: vX.X.X ... / 调研对象: ... / 招生匹配度: 🟡 ... / 论文产出: N 篇...」). 元信息 (招生匹配度 / 论文产出数 / L? 数据源状态 / 调研对象) 是 docx TL;DR callout 内容, **应在 docx 里写, 不在 chat 复述**. 正确 chat 行为 = 跳过 preamble → 抓取 → `lark-cli docs +create --content @<xml>` → 输出 docx URL 单行收尾. 详见 `SKILL.md §Output Discipline 硬要求`.

一个 lark-doc v2 兼容的 XML 字符串(结构见 `report-template.md`),要能直接喂给:

```bash
lark-cli docs +create --api-version v2 \
  --title "{学校} {老师}" \
  --content "<the XML>"
```

## 合成流程(8 步,严格顺序)

### 1. 抽取并标准化基本信息

从 L1 + L4 数据里抽 7 个字段:
- 姓名(中英文)
- 职称(标准化:教授/副教授/助理教授/研究员/副研究员)
- 行政职务(可空,空就 `—`)
- 学术荣誉(青千/优青/杰青/长江/院士)
- 学术兼职(主编/编委/AC)
- 研究方向(3-5 个关键词,中英对照)
- 学术服务(NeurIPS/CVPR/ICCV AC 等)

**不知道的字段填 `—`,不写空字符串**。

**🚨 多源交叉验证硬要求**(避免况琨 case 办公地址"则通楼 108" vs "Room 613 CGB" 两处矛盾):
- 关键字段(办公地址、邮箱、当前职位、入学年份)**至少 2 个 L1/L4 源独立验证**后才写入
- L1 ZJU 主页 vs L1 个人主页 / L4 web_search / L4 CCF 档案**任 2 个**一致 → 写入,标注 `[✓ L1+ZJU+L4 验证]`
- L1 ZJU 主页 vs 其他源**不一致** → **写入并标 ⚠️ 矛盾**:例如 `办公地址:则通楼 108(⚠️ ZJU 主页),kunkuang.github.io 写 "Room 613 CGB" 矛盾,以 ZJU 主页为准`
- **严禁**只采信单一源 + 不标矛盾

### 2. 计算 TL;DR 关键数字

| 数字 | 来源 |
|------|------|
| 近 3 年论文数 | L2 paperList(过滤 year >= 当前年 - 2) |
| CCF-A / CCF-B 数 | **v0.1 不实现,留 N/A** |
| 通讯作者占比 | L2 论文中,该老师是最后作者 / 通讯作者的占比 |
| 合作者高频榜(>5 篇) | L2 paperList authors 字段统计 |

### 3. 匹配度评分(招生匹配度灯号)

三档:🟢 高 / 🟡 中 / 🔴 低

| 信号 | 🟢 高 | 🟡 中 | 🔴 低 |
|------|------|------|------|
| 方向契合(用户方向与老师 ≥ 2 个近 3 年方向重叠) | ✓ | 部分 | ✗ |
| 论文产出稳定(近 3 年均 ≥ 10 篇) | ✓ | 部分 | ✗ |
| 招生信号(主页明示"招博士生") | ✓ | 隐含 | ✗ |
| 实际带生者信息(找到合著者 / 主页学生名单) | ✓ | 推测 | ✗ |
| 导师时间投入(主页明示行政岗:本科生院院长/副院长/党委书记/校长助理 等) | 一线 PI | 部分行政 | 纯行政 / 已离一线 |

**基础判定**:
- **3 项绿 + 1 黄** → 🟢 高
- **2 项绿** → 🟡 中
- **≤ 1 项绿** → 🔴 低

**行政岗自动降档规则**:
- 导师主职为**非研究岗**(本科生院院长/校领导/党委书记/教育部 AI 专家组组长 等)且**本人一作/共一近 3 年顶会论文 = 0** → **自动降一档**(从 🟢 降 🟡,从 🟡 降 🔴)
- 理由:行政岗 + 通讯 PI 模式 = 实际带生时间 < 50%,不是单纯"产出高"的绿灯信号

### 4. 作者位置统计(通讯 ≠ 实际带生)

**核心概念(必读,反直觉)**:
- **通讯 / 末位 author = senior author / PI 挂名**,**不**等于"实际带生者"
- 一个导师可以 80% 论文挂通讯(产出强),但**实际带生者是青年教师**(通讯只是行政挂名,不是亲手指导)
- 实际带生要看:L4 合著频率(青年教师高频合著)/ 主页学生名单 / 学生毕业去向

**统计方法**:
从 L2 paperList 抽 10-20 篇近 3 年论文,统计该老师在 author list 的位置占比:
- 末位 / 通讯 = senior 挂名(常见 PI 模式)
- 第 1 位 = 一作(说明他亲自下场)
- 第 2 位 = 共一(常是合作者 / 学生共一)
- 中段 = 合作者

**判读规则**:
- 末位/通讯占比 ≥ 70% **且** 本人一作 = 0 → 写"**通讯 PI 模式**(产出强但实际带生疑为青年教师)"
- 末位/通讯占比 ≥ 70% **且** 本人一作 ≥ 1 → 写"**active PI 模式**(亲自下场 + 通讯指导)"
- 第 1 位/共一占比 ≥ 30% → 写"**合作者模式**(非主要带生)"
- 比例都不突出 → 写"**数据不足,无法判定**"

### 5. 风险灯号

| 信号 | 灯号 |
|------|------|
| L1-L4 全失败(信息黑洞) | 🔴 高 |
| L1 成功但近 3 年可验证论文 < 3 篇,或方向匹配论文 0 篇 | 🟡 中 |
| 其他 | 🟢 低 |

如果**多个信号叠加**(方向变化快 + 实际带生者不确定 + 招生名额信息缺失)→ 升一档。

### 6. 选 10 篇最相关论文

按以下优先选 10 篇:
1. 近 3 年(2024-2026)且 venue 是顶会/顶刊(CCF-A / NeurIPS / ICLR / ICML / CVPR / ICCV / ECCV / ACL / EMNLP / KDD / SIGIR / AAAI / IJCAI / Nature / Cell / Science / TPAMI)
2. 用户方向相关的优先(若用户给了方向)
3. 综述 / Benchmark 类优先(套磁信好引用)
4. 该老师是末位/通讯的优先(说明他深度参与)

每个论文填 5 个字段:类型 / 角色 / 核心贡献 / 与你关联 / 技术关键词。

### 7. 方向分布与趋势(精确统计,禁止估算)

**硬规则**:方向分布必须**精确计数**,禁止"约 35%" / "大致 30%" / "大部分" 等模糊描述。

**统计方法**:
- 从 L2 / L3 / L4 抓取的 paperList 中,**全量**抽取 2024+ 论文(不是 selected)
- 按大方向(LLM-Agent / 因果 / 垂域 / 端云 / CV / 联邦 等,事先定义好分类规则)关键词聚类
- 输出**精确数字 + 占比**(百分比 = 该方向数 / 论文总数,保留整数)
- 例:`LLM-Agent: 18 篇 (32%)` 而不是 `LLM-Agent 约 30%`

**数据源标签**:每个数字必须标注来源(来自 L2 S2 paperList / L3 DBLP / L4 AMiner 聚合),不要把不同源的数字混在一起报。

**按年趋势**:
- **禁止**用 `████████` 字符画(粗糙、无法精确、信息密度低)
- **必须**用 table + emoji:每年 1 行,每方向 1 列,数字精确到个位
- 表格示例见 `report-template.md` § 方向分布

**核心观察**放 callout 时,可以有定性总结(转型 / 收缩 / 爆发),但**不要**改精确数字。

### 8. 套磁邮件草稿

必含:
- 1-2 句开篇(我是谁 + 为什么联系你)
- 引用 1-2 篇具体论文(venue + 标题 + 一句技术点)
- 与用户方向连接(为什么契合)
- 简历附件暗示(可不上传,但要提"详见附件 CV")

**不要**用"我仰慕您已久""您的研究令人敬佩"等空话。**必引具体论文**。

**arXiv/DOI inline link 硬要求**:每篇被引用的论文,在 (venue year) 之后加 `<a href="{arXiv abs URL}">arXiv</a>` 或 `<a href="https://doi.org/{DOI}">DOI</a>` 链接(如有)。飞书 docx 支持 inline link,user 可直接跳转原文。**禁止**只放裸论文标题。

**🚨 论文条目 6 行 paper card 硬要求 (2026-06-08 v0.3.0, 违反 = skill 协议破坏)**:

每篇被引用的论文, **必须**用 6 行 paper card 格式 (取代 v0.2.5 的紧凑 `<p><b>...</b></p>` 格式):

```xml
<h4>{N}. {论文完整标题 (verbatim)}</h4>
<p>作者：</p>
<p>{作者 1, 作者 2, ..., Fei Wu（吴飞）, ..., 末位作者}</p>
<p>发表：{venue} {year} ({角色})</p>
<p>arXiv：<a href="https://arxiv.org/abs/{arxiv-id}">https://arxiv.org/abs/{arxiv-id}</a></p>
<p>paperscool：<a href="https://papers.cool/arxiv/{arxiv-id}">https://papers.cool/arxiv/{arxiv-id}</a></p>
```

5 字段前缀必含 (`作者：` / `发表：` / `arXiv：` / `paperscool：`), 全作者列出(无 et al.), Fei Wu 显式标 `Fei Wu（吴飞）`. 完整模板见 `report-template.md §5.1`.

**🚨 数据稀疏硬规则 (2026-06-05)**:

如果 L2 / L3 抓到的近 3 年论文 < 5 篇,套磁信必须**显式说明**:
- "由于公开资料有限,我对您课题组的了解主要来自 {具体来源,如 L1 主页研究方向 + L4 个人网站},**部分引文可能不准确**,如能获得您的近期组会 paper list 将非常有帮助。"
- **禁止**在数据不足时硬引用 L2 之外的 arXiv 搜索结果(那是"幻觉引文")
- 改为**请教式**套磁:"如果您能推荐 1-2 篇您认为代表课题组方向的论文,我将非常感谢"——把"信息不足"转化为"请教机会",反例的"假装内行"是套磁信最差模式

## 反模式(必避)

- ❌ 编造论文 / 编造 h-index / 编造学生名字 → 一律标 `[待验证]`
- ❌ 用 markdown 表格 → 飞书 v2 不渲染,会变成 plain text
- ❌ 不用 callout,全用纯文字段落 → 视觉密度太低
- ❌ TL;DR 超过 6 行/列 → 信息过载,用户抓不到重点
- ❌ 套磁信不引具体论文 → 套磁信无差别化
- ❌ 把 L1 自报的"研究方向"原样照抄(可能是空话) → 用 L2 论文关键词反推
- ❌ 不标数据缺口 → 用户不知道哪里需要补
- ❌ **手动 `(1) (2) (3)` h4 编号 / 内联 `① ② ③` 字符** → 飞书 outline 不识别,违反 = skill 协议破坏(SKILL.md 硬规则)
- ❌ **`████████` 字符画趋势图** → 用 `<table>` + 精确数字(LLM-prompt §7)
