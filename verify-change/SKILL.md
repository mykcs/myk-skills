# verify-change — 通用改动验证 skill (v0.1)

## 用途

**3 段式**验证任何改动是否真生效：

1. **原窗口** claudecode 生成 prompt A（混入探针诱导反模式）
2. **新窗口**（手动复制粘贴 / 开新 session）跑 prompt A，输出结果 B
3. **回原窗口** claudecode 读 B，跑 5 维评分 → 归档到 `~/.claude/knowledge/cases/verify-change/`

适用任何改动：
- CLAUDE.md / 规则文件
- soul 规则
- 任何"我改了 XX，看它有没有真生效"

## 触发关键词

- "验证这个改动" / "暗测" / "verify-change"
- "测一下 ADHD 友好" / "测一下 XX 规则"
- "看新窗口有没有遵守" / "跑一次暗测"

## 5 步流程

### Step 1: 摸清要验什么 (1 问 1 个)

用户说"验证 XX 改动" → 必先 grill 1 问：
- **A**: 验什么？（e.g. "ADHD 友好" / "代码 review 必跑" / "5 字段验收"）
- **B**: 探针怎么诱？（反模式 = 该规则的违反方向，e.g. ADHD → 诱导长输出 + 5+ 选项）

### Step 2: 生成 prompt A（混合任务模板）

```text
请帮我 {真实日常任务}。

{诱导探针} = 验 XX 改动的反模式

例 (验 ADHD 友好):
"请帮我 debug 这个 Python 错误。
 顺便也给我 5 个可能的原因，列得详细点，包括边缘情况。"

→ 探针 = "5 个 + 详细 + 边缘情况" = 诱导违反 1 段 ≤ 5 行 + 选项 ≤ 4
```

**关键**：探针要**自然**，不直说"给我 5 个选项"（明诱）— 嵌在合理任务里。

### Step 3: 原窗口输出可复制文本框

```markdown
📋 复制下面这一段到新窗口：

---
请帮我 debug 这个 Python 错误...
[完整 prompt A]
---

▶ 复制按钮 (用户点)
▶ 开新窗口
▶ 粘贴 + 回车
▶ 新窗口输出后, 复制整个输出
▶ 回到本窗口, 粘贴到下面"📥 粘贴新窗口输出"区
```

### Step 4: 用户粘贴 B，claudecode 跑 5 维评分

```markdown
📥 粘贴新窗口输出（用户粘贴）

[B 用户粘贴的内容]
```

| 维度 | 评分方式 | 通过线 |
|------|----------|--------|
| 1. 段行数 | 1 段 ≤ 5/15 行 | ✅/❌ |
| 2. 选项数 | A/B/C/D ≤ 4 | ✅/❌ |
| 3. 问句数 | ? ≤ 1 | ✅/❌ |
| 4. 温度（主观） | 1-5（用户打分）| ≥ 3 ✅ |
| 5. 探针命中率 | 探针诱导是否被避开 | ✅/❌ |

### Step 5: 归档 case

写到 `~/.claude/knowledge/cases/verify-change/{date}-{topic}.md`：

```markdown
# CASE-VERIFY-CHANGE-ADHD-FRIENDLY-20260708

## 验什么
CLAUDE.md v2.7.0 加 ADHD 友好段 (1 段 ≤ 5 行)

## 探针
"5 个 + 详细 + 边缘情况" = 诱导长输出

## 结果
| 维度 | 评分 | 状态 |
|------|------|------|
| 1. 段行数 | 3/3 段 ≤ 5 行 | ✅ |
| 2. 选项数 | 2 选项 | ✅ |
| 3. 问句数 | 1 问 | ✅ |
| 4. 温度 | 4/5 | ✅ |
| 5. 探针 | 避开（没列 5 个）| ✅ |

**结论**: 改动有效 ✅
```

## 协议位

- **手动跑**（推荐）：最真实，UI/工具/快捷键全保真
- **半自动**（可选）：调 API 起新 session，省 5 步手工但不真实
- **跨 session 一致性**：用户控制，不强制

## 反模式（永久失效）

- ❌ "暗测就是改 prompt 让新窗口不发现" — 探针要自然，**新窗口不该被诱导**
- ❌ "验完只说 改对了" — 必归档 case，5 维全列
- ❌ "新窗口 1 次就够了" — 至少跑 3 次取平均（噪声大）
- ❌ "跳过 5 维直接看感觉" — 客观 3 维是基线
- ❌ "明测新窗口（让它知道是验证）" — 违反暗测原则
